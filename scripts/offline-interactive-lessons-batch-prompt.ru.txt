Роль модели
-----------
Ты — редактор образовательной платформы для разработчиков. Все уроки на русском,
практичные, без воды и без упоминаний того, что материал «запасной» или «временный».

Задача
------
Сгенерируй РОВНО 300 разных интерактивных уроков в одном машиночитаемом JSON.
Каждый урок самодостаточен. Тематика и глубина — как у качественных tech-блогов
и официальной документации (паттерны, API, отладка, архитектура, безопасность).

ВАЖНО ПО ОБЪЁМУ
---------------
300 объектов в одном ответе часто не помещаются в лимит токенов. Делай выдачу
ПОРЦИЯМИ: например 10 файлов по 30 уроков, или 15×20, и явно подписывай
"batch_index": 1..N, "batch_total": N в корне каждого JSON. Все порции — один
и тот же формат поля "lessons".

Распределение по темам (ровно 300)
----------------------------------
Используй поле topic_slug ТОЛЬКО из этого списка (по 25 уроков на каждый slug):

  react, typescript, docker, kubernetes, graphql, rust, python, ai-ml,
  security, devops, system-design, web-apis

(12 × 25 = 300.)

Поле difficulty для каждого урока: одно из: "beginner" | "intermediate" | "advanced".
Чередуй уровни внутри темы правдоподобно (больше intermediate, меньше extreme).

Структура ОДНОГО элемента массива "lessons"
--------------------------------------------
Каждый объект:

{
  "topic_slug": "typescript",
  "difficulty": "intermediate",
  "title": "…",
  "summary": "…",
  "why_it_matters": "…",
  "source_urls": ["https://…", …],
  "phases": [ { … }, { … }, { … } ],
  "flashcards": [ { "question": "…", "answer": "…" }, … ]
}

Требования к контенту
---------------------
• title — короткий русский заголовок, без кликбейта.
• summary — 1 предложение-вступление по сути материала.
• why_it_matters — почему это полезно разработчику на этом уровне.
• source_urls — 2–6 публичных HTTPS-ссылок (документация, спецификации, качественные
  статьи). Релевантны теме урока; выдуманные URL запрещены.

Интерактив: phases (ОБЯЗАТЕЛЬНО)
--------------------------------
• Ровно 3 элемента в "phases" — три логические части ОДНОЙ темы (~100% материала
  поровну, без дублирания, последовательное углубление).
• В каждой фазе:
  - "theory" — связный текст: несколько абзацев на русском.
  - "code_examples" — массив строк; КАЖДАЯ строка — пример кода (учебный или рабочий);
    в первой строке примера комментарий с языком, например: // TypeScript
  - "quiz" — РОВНО 5 объектов. У каждого:
      "question": строка,
      "choices": [ "…", "…", "…", "…" ]  — ровно 4 варианта,
      "correct_index": целое 0..3 (индекс верного варианта).

flashcards
----------
• Минимум 5 карточек на урок; вопрос и ответ на русском, конкретные.

Корневой JSON каждой порции
---------------------------
{
  "batch_index": 1,
  "batch_total": 10,
  "lessons": [ … ]
}

Правила валидации (соблюдай строго)
-----------------------------------
1) В "phases" всегда длина 3.
2) В каждом "quiz" всегда длина 5.
3) У каждого вопроса ровно 4 non-empty строки в "choices".
4) correct_index в диапазоне [0,3].
5) В каждой фазе минимум один непустой элемент в "code_examples".
6) Все тексты на русском (кроме кода, имён API и т.д.).

Формат ответа
-------------
Верни ТОЛЬКО валидный JSON (без markdown-ограждений ```, без комментариев,
без текста до или после). Если одна порция — один объект с "lessons".
Если несколько порций — повтори запрос для следующих batch_index.

Уникальность
------------
Уроки не должны повторять друг друга по заголовку и по ядру темы; внутри одной
темы (topic_slug) разные подтемы (хуки, контекст, middleware, типы, и т.д.).

Конец промпта.
